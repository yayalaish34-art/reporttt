ממשק בעברית, RTL, עם סרגל התקדמות אחד ובלי תפריטים מקוננים.

```
לוח בקרה   ← רשימת פרויקטים + "חיזוי חדש"
כללי רגולציה ← בדיקה והפעלה (APPROVER)

פרויקט: מסמכים | מודל | שאלות | חישוב | תוצאות | המלצות | דוח
```

## מסך אימות מודל

התוכנית במרכז. סרגל כלים אחד:

| כלי | פעולה |
|---|---|
| כיול | שתי לחיצות על מידה ידועה, והזנת האורך במטרים |
| נקודת ייחוס | לחיצה על נקודה זהה בכל הקומות |
| חדר | לחיצות ליצירת פוליגון, ולחיצה כפולה לסגירה |
| כבל | לחיצות לקו, ולחיצה כפולה לסיום |
| שנאי / לוח | שתי לחיצות לפינות התיבה |
| בחירה | לחיצה על רכיב: עריכה, מחיקה או הזזה |

שינוי כלשהו אחרי MODEL VERIFIED מבטל את האישור אוטומטית. זה נרשם ב-`audit_log`.

## שאלון דינמי

השאלות נגזרות רק ממה שחסר במודל. אין שנאי — אין שאלות שנאי. אין busbar — אין שאלת רוחב פס. כל תשובה עדכנית מסירה את השאלה מיד. שאלה מקבלת ערך ובסיס (`RATED`, `DESIGN`, `MEASURED`, `ESTIMATED`), ואין בה ערכי ברירת מחדל ממולאים מראש.

## מסכי חסימה

כשאי אפשר להנפיק דוח סופי, הדוח יכול לצאת רק כטיוטה עם סימן מים, ומוצג:

```
לא ניתן להנפיק דוח חיזוי סופי.
מידע חסר:
• TR-01: חסר זרם
• קומה 2: חסר גובה מפלס
• כלל רגולטורי: אין כלל מאומת למשרד / שהייה ממושכת
```

## מעקב (Traceability)

לחיצה על מספר בטבלת התוצאות פותחת חלונית עם: מסמך מקור, קלט, נוסחה, שיטת שילוב, הנחות, כלל רגולטורי וגרסת תוכנה.

## החלטות

### ה16. עורך אחד על התוכנית במקום טפסים
- **מדוע:** הקשר הגאומטרי בין מקור לחדר הוא העיקר, והוא נבדק הכי טוב בעין.
- **חלופה:** הזנת קואורדינטות בטבלה. נשארת זמינה לעריכה מדויקת (גובה Z, זרם), אבל לא כמסלול הראשי.
- **סיכון:** דיוק של לחיצת עכבר. הערכים ניתנים לתיקון ידני, והכיול מוצג בבירור.

### ה17. Heatmap עם ערכים מספריים, בלי סטטוס בצבע
- **מדוע:** דרשת שצבע לא יסיק סטטוס. לכן הצבעים לתצוגה בלבד, והסטטוס מופיע רק בטבלה ומגיע ממנוע הרגולציה.
- **סיכון:** עומס חזותי ברשת צפופה. מוצג ערך בכל תא רק כאשר התא גדול מספיק על המסך, והמרבי של החדר מוצג תמיד.
