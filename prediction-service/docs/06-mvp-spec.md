# שלב 6 — אפיון MVP 1

## בתוך MVP 1

| יכולת | הגדרת סיום |
|---|---|
| פרויקט ומסמכים | פתיחת פרויקט, העלאת PDF/PNG/JPG בגרסאות |
| כיול ידני | סקייל ונקודת ייחוס לכל קומה |
| הצבה ידנית | כבלים, לוחות, שנאים, חדרים |
| חישוב תלת-פאזי | Biot–Savart פאזורי, קבוצות קוהרנטיות, 3D בין קומות |
| רשת | גודל ניתן לשינוי, כמה גבהים |
| Heatmap | על התוכנית, ב-mG, עם ערכים מספריים |
| שהייה | הצעה לפי שם ואישור אנושי, הזנת שעות |
| טבלת תוצאות | כולל סטטוס ממנוע הרגולציה, ומעקב למספר |
| רגישות | Expected / Conservative / Worst-case |
| דוח PDF | 22 סעיפים בעברית, סימן מים לטיוטה, זרימת אישור |
| validation | הזנת מדידות, השוואה, שמירת שגיאה |
| audit + readiness | רישום שינויים, חסימת הנפקה |

## תנאי מעבר ל-MVP 2

שאלת המפתח: **האם המנוע תואם מציאות?** תנאי המעבר הם:

1. לפחות 3 מקרים אמיתיים ב-`validation_cases/`, עם מדידת שטח ו/או השוואה לתוכנת חיזוי קיימת.
2. **סף השגיאה המותר ייקבע על ידי בעל המקצוע**, ולא על ידי המערכת.
3. אישור של בעל מקצוע.

## קריטריוני קבלה ל-MVP 1

- כל 10 בדיקות המנוע והרגולציה שביקשת עוברות.
- מסלול מלא (בדיקת API): פרויקט, העלאה, כיול, חדר, כבל, שאלות, אימות, חישוב, דוח, אישור.
- בלי כלל פעיל: הסטטוס `REGULATION_REVIEW_REQUIRED`, והנפקה נחסמת.
- ENGINEER לא יכול לאשר דוח.
